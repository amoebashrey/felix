// the problem

Engineers were drowning. Support reps were waiting. Both deserved better.

Before Felix, every tech blocker in your Slack support channel went straight to whoever was around. The same questions came back week after week — calling limits, CRM auth, dashboard timeouts — eating hours of engineering time on problems that were already solved.

Worse, when issues did need engineering, they landed on the wrong team, bounced around, and arrived stripped of context. Support reps waited. Engineers context-switched. Nothing moved.

Repetitive issues drain engineering time.

The top 20 questions in #tech-problems are the same every week. Engineers were answering them by hand, one Slack thread at a time.

Wrong-team routing wastes hours.

An SMS bug pinging the CRM team, a dashboard issue routed to infra. Hours lost in handoff before anyone with the right context even sees it.

Context evaporates on every escalation.

By the time an engineer picks up the thread, half the relevant details are buried three scrolls up. Repro steps, lead IDs, error messages — all somewhere in the noise.

// the three paths

Felix doesn't try to be clever. Every triage decision lands in one of three buckets.

The discipline is what makes it useful — support reps always know what to expect, and engineers always know what Felix has already tried.

Path A · Resolve

Felix answers it himself.

trigger: KB has a high-confidence match for the issue (similarity above 0.65).
behavior: Felix posts the resolution steps inline, cites the KB section, and asks the support rep to react with 👍 if it worked or 👎 if it didn't.
Riya P.: CRM session timed out again
felix: Looks like the session timeout. Try: incognito → log in fresh. Source: KB §4.
outcome: Support rep reacts. Decision logged to Supabase.
Path B · Ask

Felix needs one more thing.

trigger: Likely match in KB, but the message is missing one specific piece of context to be certain.
behavior: Felix asks exactly one question. No interrogation, no "could you provide more info." One question, scoped to what would unlock the answer.
Alex M.: Dialer is making weird noises
felix: Is it static, echo, or no sound at all? That'll narrow it to either KB §1 or KB §3.
outcome: Support rep replies. Felix re-evaluates and either resolves or escalates.
Path C · Escalate

Felix hands it off cleanly.

trigger: No KB match, or message indicates an incident (5xx errors, "down," "broken for everyone").
behavior: Felix routes to the right team with a one-line summary of what's known and what's missing. Then steps back from the thread.
Sam K.: Homepage broken on iOS Safari
felix: No KB match. Routing to @frontend-team — reported by Sam K., iOS Safari, homepage scope.
outcome: Frontend team takes over with full context. Felix exits.

// faq

Frequently asked.

Is Felix replacing engineers?

No. Felix handles the repetitive stuff — the same twenty questions support reps ask every week. Engineers get more time on the work that needs engineering. The escalation path is faster, not absent.

What happens if Felix is wrong?

Support reps react with 👎. That's a signal: the KB entry needs editing, or the question pattern is new and needs a new entry. Wrong answers don't disappear quietly — they get logged, reviewed, and either fixed or used to bootstrap a new KB section.

Why not use a generic AI bot?

Because a generic bot would hallucinate domain-specific answers and route everything to whoever it thought was an "engineer." Felix only resolves when it has a real KB match. When it doesn't know, it asks one question or escalates — it doesn't guess.

How is the KB maintained?

Today: hand-authored from real resolution threads, reviewed before publishing. Next quarter: 👎 reactions auto-generate draft KB entries, and there's a lightweight admin UI so KB edits don't need a PR.

What data does Felix log?

Every triage decision: the original message, the path chosen, the KB section cited (if any), the reaction, and any follow-up. Stored in Supabase. Used to compute resolution rate per domain, false-positive rate, and which KB sections actually pull their weight.
